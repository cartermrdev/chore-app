# People can belong to many Households; signup is closed

A Person is a single login identity that can hold Memberships in several Households, for example a child with separated parents or a grandparent's house. Every record is therefore scoped to a Household, never to a Person. Each Tag belongs to exactly one Household, so a Scan finds the Household from the Tag and never asks the Person to choose one. Even so, the first release is a private instance with no public signup: the first Admin is seeded, and everyone else arrives by Invite. Supporting several Households per Person costs little now and is painful to retrofit later. Open signup brings abuse handling, email delivery and billing, none of which v1 needs. Because the schema is already scoped per Household, opening signup later becomes a product decision, not a migration.
